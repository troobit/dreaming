## [Unreleased]

### Added

- Replay gate (task 25): `replay.ReplayGate` replays a change to a skill, rule, `CLAUDE.md` or `AGENTS.md` that cites session observations before its checks. Up to `replay_max_sessions` sessions showing its pattern, never forgotten ones and only those with a complete recorded opening prompt, each run twice on the tool-free replayer: once without an instruction and once with the changed files as its only instruction. A reviewer-role call with the new `judge` prompt and schema judges both answers. A change to the lenses re-runs the reader on its earlier Read steps' stored inputs. A change to another role prompt is held because that role's inputs are not kept (Decision 17). The change, and its whole branch, is held when the problem recurs with it in more than `replay_max_recurrence` of the sessions that showed it without (an unclear judgement counts as recurrence), when fewer than `replay_min_sessions` can be replayed, when the remaining budget cannot cover the replay, or when its calls ran on more than one backend. Replay calls count against the budget, a resumed Adopt step reuses their answers, and results are stored in `replays` and shown in the report as association. Lens and role-prompt paths count only in the instruction repository.
- Adoption (tasks 23–24): each repository with changes gets a work copy under `~/.dreaming/work/<run>/<repo>` on `dream/<run>` from its default branch. The author edits only there, and the program commits one change per commit with `Dreaming-Change` and evidence trailers after the generate commands. Public repositories are scanned (`scan.py`) for transcript text not already in the repository, credentials and listed names, and a failing change is withheld as a patch under `~/.dreaming/patches/`. The Adopt step runs once per linked group. It checks the merge of the dream branch in a separate worktree with its own lint and test commands, then fast-forwards the user's checkout to the tested merge only when auto-apply is on and the checkout is clean, on the default branch and unmoved. It then deploys, reverting with a `Dreaming-Revert` trailer and redeploying when a deploy fails. Linked repositories are preflighted and rolled back together, and adoption steps are recorded durably, with a merge's state read from git. A resume after a first merge makes no further merges and reports finish and undo commands, and a later dream skips a repository merged but not deployed. User reverts are detected as rejections and the program's own as failures. A change with fetched content or a currency change keeps its branch unmerged.
- Run and session operations (task 22): `dream api` gains `dream.start`, `dream.status`, `dream.resume`, `dream.discard`, `dream.report`, `session.register`, `session.forget` and `session.restore`, and the CLI gains `dream resume`, `dream discard`, `dream report`, `dream forget` and `dream restore`. Discarding deletes the run's unmerged branches, work copies and rows, keeping a `discarded` run row, and is refused with the finish and undo commands once any repository was merged. Backends are probed on first use (`run.ProbedBackends`).
- Dream report (task 29): `report.Writer` writes `~/.dreaming/reports/<run>.html` in the exit path of every run, using the review page's CSS and shell vendored from agentic-coding with their source revision. It covers statistics, retained knowledge, learning recommendations, repository changes with their evidence, state and merge or revert commands (each followed by generate and deploy), candidates with rank signals and reasons, research and currency findings with escaped titles and http(s)-only links, unmerged earlier branches, changes to checks, restrictions and tool lists, and forgotten sessions. The browser opens only for the user's own dreams, and a browser failure never fails the dream.
- Dreaming decisions Q121–Q124 and Decision 17.

- Research step (task 20): `research.ResearchPhase` asks the researcher one question with the candidate it serves and the repositories and knowledge folders that exist, lists missing ones as unavailable without blocking, and stores findings with their sources in `research_findings`, apart from observations. A finding counts as fetched unless every source is a local repository or knowledge-folder path.
- Author step (task 20): `author.AuthorPhase` re-checks a candidate's evidence and cited files on the default branch before any call and defers it with the reason when they no longer hold. The author gets the evidence, counter cases from contested knowledge on the same pattern, research findings, the cited files and the repository's `CLAUDE.md`/`AGENTS.md` read from the default branch, with large files left for it to read. Changes must be edits to sections that exist in the current files, each citing a supporting case from what it was given; otherwise the candidate is discarded with the reason. A stored change records its edits, depends-on repositories, `external_input` and a commit message whose `Dreaming-Evidence` trailers the program writes. Learning recommendations keep research apart from evidence, and interactive skill steps are recorded as deferred. `author.linked_groups` gives the repositories adopted together.
- `dream api` (task 21): one JSON request on stdin, one response on stdout, with `knowledge.recall`, `knowledge.search` and `knowledge.get`. These return retained revisions only, filtered to active, applicable, supported knowledge and open learning recommendations unless `include` asks for more, ordered by scope specificity, confidence, recency and id within a limit in estimated tokens, with redacted quotes, modality and availability on every evidence reference.
- `knowledge.feedback` (task 21): revisions marked cited or present-only with the outcome and its basis, idempotent by feedback id, queuing the items for reassessment (the reviewer sees the feedback); user corrections, rescoping and dismissals (optionally excluding the evidence) as revisions by the user; learning dispositions.
- `knowledge.export` and `knowledge.import` (task 21): a versioned `dreaming-export` document that imports into a fresh store and exports again unchanged; importing twice adds nothing, forgotten sessions stay excluded, and imported evidence never counts toward the new store's promotion thresholds.
- Store migrations v5 (research and authoring columns) and v6 (`imported` markers); the author schema gains `deferred_steps`; dreaming decisions Q108–Q120.

- Dreaming observations (task 15): `redact.py` (agentic-coding's credential patterns plus `sk-`, `github_pat_`, `AIza` and JWT, repeated to a fixpoint) and `observe.gate`, which keeps a reader observation only when its quote matches the cited entry (whitespace-normalised, before redaction), its lens was asked for and a user statement quotes an entry presented as the user's; outcomes cited from the assistant become `unknown`. Evidence ids are content hashes, so rereads add nothing.
- Read steps (task 16): `observe.ReadPhase` plans one Read step per selected or unparseable session and a Review step after them, reads each session part by part through the dispatcher, stores gated observations and rejections in the step's transaction, records a session that fails twice as `failed`, and stops before the next call when the session is forgotten. Reader and reviewer calls record the sessions their input held, and selection skips dream call sessions whose input held a forgotten session. `run.Phase` gains an optional `failed` hook.
- `dream trial reader --backend NAME [--sessions N]` (task 17): the schema-valid rate, quote-match rate and tokens of one backend on the newest recorded sessions, with no store writes.
- Knowledge rules (task 18): `knowledge.judge` (promotion at `min_sessions` distinct interactions, confirmed success for workflows with confirmed failures counted against, user statements only for learning, contested on conflicts unless the user settles them), `knowledge.Reviser` (create, revise, supersede, contest, dismiss, confirm and merge with version checks, a per-scope revision cap, equivalence and dismissal rules, scope derivation and confidence caps, append-only revisions), `scope_applies`, `retrieval_key` and learning dispositions.
- Review step (task 19): `review.ReviewPhase` clusters unassigned observations by lens and normalised key, joins exact-key matches to their pattern, gives the reviewer ranked bounded summaries with run records, applies assignments, pattern merges, knowledge operations and candidates under the rules (9.13, 9.14, 4.5, 15.3), records every refusal with its reason, stores candidate rank and signals, and adds Research and Author steps in the same transaction.
- Store migration v4 (`rejections`, `candidates`, `questions`, `patterns.merged_into`, `learning.pattern_id`); dreaming decisions Q96–Q107.

- Dreaming backend dispatcher (task 11): one retry per backend, then the role's next backend after two transport failures; two schema failures fail the input, and `breaker_k` schema failures in a row disable the backend and give its failed inputs to the next one. A usage limit with a reset time within `max_usage_wait` sets the run `waiting` with the reset time and a notice naming `fallback_on_usage_limit` and each backend's context size, sleeps and repeats the call; the classifier covers Claude's and Codex's clock-only and dated messages. Missing usage is estimated and flagged, and every output is checked against its role schema (`schema.py`) whatever the backend's structured-output option did.
- Claude Code and Codex adapters (task 12): per-call MCP config holding only the role's servers and tools, with devtools' agent-launching tools removed and server secrets referenced from `<SERVER>_<SECRET>` environment variables, never written into a command line; Claude runs with the probe-confirmed isolation flags, an explicit tool list without `Agent`, `dontAsk` permissions and a session id recorded on the calls row before the call; Codex saves its event stream under `runs/<id>/codex/` and is killed on any agent-launch event; `probe.adapter` builds a backend from a usable probe result.
- Direct LM Studio adapter (task 13): the run id as the client thread id at the head of the request body, the loaded model and its context read from `/api/v0/models` before every call, nothing sent for a model that is not loaded or an input larger than its context, tool-using roles refused, and server error text kept in the failure.
- Roles and the instruction set (task 14): `roles.py` loads role prompts, output schemas and lenses from a run's snapshot, builds prompts with the schema and the input between data markers, sizes inputs for the smallest context in the fallback list, packs reviewer input from pattern summaries and short evidence quotes (never transcripts), routes earlier dreams' sessions to the `dream-behaviour` lens, and gives the replayer only the opening prompt and the instruction under replay. `instructions/` gains `lenses.toml` (every 7.2 lens plus `dream-behaviour`), `roles/{reader,reviewer,researcher,author,replayer}.md` and strict-mode `schemas/*.json`; `config.example.toml` adds the shared MCP definitions and the researcher's pull-request tool.
- Dreaming decisions Q89–Q95.

- Dreaming run engine (tasks 8–10): `dream run` takes a non-blocking lock, records the run (requester, revision, selection, overrides, budget, configuration snapshot) and continues in a detached child that holds the lock; a second start exits 4 and changes nothing, and the next start resumes an interrupted run, keeping its selection and overrides and accepting only backend choices. `--wait` exits with the run's code (0 complete or budget exhausted, 1 interrupted, 2 usage, 4 already running, 5 partial).
- The step table (`steps.py`): steps with stable keys and dependencies, follow-up steps committed with each result, a `calls` row written before every model call and its raw output stored as soon as it returns, so a resumed run applies stored output instead of calling again.
- Budgets (`budget.py`): tokens summed from recorded calls, a wall-clock limit that does not count time spent waiting for a usage limit to reset, the review and authoring reserve on Read calls, and `budget_exhausted` when the run's own limit stops model work.
- `dream run --dry-run [--json]`: the sessions a start would read, each role's backends labelled cached, unprobed or unavailable, and the budget, with no model call and no change to any file or row.
- `dream status [RUN] [--plan]`: a run's state, and its steps rendered as a rune task file at `runs/<id>/tasks-dream.md`.
- Versioned installs: `make install` builds the committed `HEAD` into `~/.dreaming/versions/<revision>/`, repoints `current`, links `~/.local/bin/dream` to a launcher and removes versions no unfinished run needs; the launcher keeps an unfinished run on the version it started with.
- Store migration v3 (`steps.seq`, `runs.active_seconds`, `runs.error`); dreaming decisions Q82–Q88.

- Dreaming sessions (tasks 6–7): session selection newest first within the session budget, reading only entries added since the last read under unchanged lens versions, with date, project, reread and scope filters (`sessions.select_sessions`). It excludes the running dream's own sessions and recently modified ones, tags earlier dreams' sessions `subject=dreaming`, de-duplicates by correlation identifier (harness content plus LM Studio server metadata), lists unparseable sessions as skipped, and splits sessions into reader-sized parts with truncation markers.
- Session attribution: harness, per-entry model, provider, local/cloud, project (a worktree counts as its repository), domain, workflow and origin. Prompts from non-interactive, registered and dream sessions are presented to the reader as role `tool`, and unmapped domains and origins are listed.
- Session registration (`sessions.register_sessions`), keyed by tool, run reference and session, accepting a source and session id or a shared-json file. Registering again with the same details changes nothing, a forgotten session is refused, and a late registration turns the session's prompts into tool prompts and marks the knowledge it supported pending reassessment.
- `sessions.record_session` and `sessions.record_skipped`, which record what was read on every source copy without clearing the forgotten flag.
- Forgetting and restoring a session (`knowledge.forget_session`, `knowledge.restore_session`) across every source copy. Counts, pattern ranking and observations given to roles leave out forgotten and excluded evidence, and knowledge items or changes whose counted support fails 4.5 or 13.3 are withheld at once.
- `backends.estimate_tokens` (`ceil(utf8 bytes / 4)`), shared by probes and session splitting; store migration v2 adds listing sizes to `sessions_seen`.
- Dreaming foundation (tasks 1–5): the `dream` package (Python 3.12+, uv, no runtime dependencies) with `make test`, `make lint`, `make test-live` and `make install`; the private home (`DREAMING_HOME`, mode 0700, refused inside any git repository); the SQLite store with additive `user_version` migrations, WAL and `migration_blocked`; configuration defaults, validation (exit 2), per-run overrides, lens loading and the start-of-run snapshot read from the instruction repository's default branch; `dream config`; backend probes for Claude Code, Codex and direct LM Studio with a cached dry-run view (`dream probe`, `dream probe --cached`); the apsis shared-json client with recorded contract fixtures.
- Dreaming decisions Q77–Q81: argparse CLI, auto-apply off by default, Codex rollouts correlate by session id, Claude models unknown through apsis 4bf9776, Codex skipped for isolated roles while bundled skills stay listed.
- Specs for `dreaming` (requirements, design, decision log, tasks, prerequisites) and `dry`, plus `specs/BACKLOG.md`.
- Dreaming Decision 16: a provider usage limit with a reset time within `max_usage_wait` makes the run wait and repeat the call; `fallback_on_usage_limit` (default off) moves to the next backend instead, and the waiting notice shows each backend's context size and, where reported, model release date.
- Dreaming design: explanation of the `flock` lock (non-blocking lock taken by the start parent, inherited by the detached child, `close_fds=True` for spawned subprocesses, resume takes the same lock).

### Changed

- A call's file tools may write only in its work copy: Claude gets the work copy as its only added directory, Codex writes in a `workspace-write` sandbox only when given one, and a writing call without a work copy reaches no other directory. Generate, lint, test and deploy commands are killed after `adoption.command_timeout_seconds`.
- The Review step detects reverts of earlier dreams' changes before the reviewer runs and plans the Adopt step after every Author step.
- The LM Studio probe checks that the model is loaded through `/api/v0/models`, so it never makes LM Studio load a model on demand.
- Reader, reviewer and replayer tool lists must be empty, and every tool must be a file tool or `<server>.<tool>`; the reader's part size now comes from `roles.input_tokens`, which also keeps room for the reply.
- Dreaming exit codes: reaching the run's own budget ends as `budget_exhausted` with exit 0; exit 5 is reserved for `partial` runs. Wait time on a usage limit does not count toward wall-clock (requirements 1.2, 5.3).
- Dreaming tasks 2, 3, 8, 11 and 22 updated for the `waiting` run status, `max_usage_wait`, lock behaviour, exit-code mapping and the usage-limit classifier.
